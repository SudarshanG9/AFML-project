## 1. Architecture boundaries found in the repository

| Owner | Checked-in package | Actual responsibility | UI consumes |
|---|---|---|---|
| Member 1 | `src/avfuse/member1_fusion/` + `scripts/day2_*` / `scripts/dayA_*` | Model adapter, attention oracle/SDPA wrapper, fake quantization policies, modality ablation, Q/K/V-boundary, memory and padding/mask diagnostics | Prediction JSONL and Day 2/Day A diagnostic JSON reports |
| Member 2 | `src/avfuse/member2_data/` | Manifest/label custody, prediction checks, metrics, paired analysis, data QA | Manifest JSONL, predictions JSONL, `metrics.json`, shortcut and overlap audit JSON |
| Member 3 | `src/avfuse/member3_runtime/` | Device/environment checks, operator and generic callable benchmarks, stage profiler, run artifacts/provenance | Benchmark JSONL, environment report, stage profile, run manifest and hashes |

The frontend is a local Streamlit reader/controller. It does not re-implement the detector, threshold calibration, metric computation, benchmark engine, or dataset decoding.

## 2. Readiness findings that affect the UI

1. `src/avfuse/member3_runtime/cli.py` only accepts `--smoke`. Without it, it raises a parser error saying that the real model is not yet integrated. The smoke command uses synthetic tensors and `DiagnosticModel`, whose head is randomly initialized. Its score is not a deepfake prediction.
2. `src/avfuse/member1_fusion/dimodif_adapter.py` strictly loads a DiMoDif checkpoint and exposes reference inference, but `predict_from_cached_features()` raises `NotImplementedError` for the three non-reference precision modes. The base `ModelAdapter` is abstract; there is no complete four-mode model factory/CLI/API in the checked-in code.
3. The repository also contains `docs/member2/results/VAL_4MODE_RESULTS.md`, a documented four-mode validation summary. That is a Markdown report, not the machine-readable `metrics.json` artifact; it conflicts with the currently checked-in adapter's reference-only implementation. The frontend labels the Markdown values as historical/documented validation evidence, not as a live backend run. The final test result is not inferred from it.
4. `Member 3` documentation states that the full four-config output writer, checkpoint-backed CLI, final run configuration storage and real-model benchmark integration still require completion. Timing primitives and artifact-integrity utilities exist, but they are not a completed real-model orchestration workflow.
5. `contracts/schemas/benchmark.schema.json` and `docs/CONTRACTS.md` describe benchmark schema v0.2 as **proposed**, pending review by Members 1 and 2. The UI validates against the checked-in file but visibly preserves that proposed status.

These are reasons to disable the real four-configuration run action; they are not frontend omissions.

## 3. Contracts and file inputs represented

### Manifest — `contracts/schemas/manifest.schema.json`

One JSONL object per clip. Required fields: `clip_id`, `dataset`, `source_id`, `identity_id`, `split`, `label`, `manipulation_type`, `feature_path`. Split values are `train`, `val`, `test`; manipulation values are `real`, `audio_fake`, `video_fake`, `both_fake`. The UI checks the checked-in JSON Schema, duplicate clip IDs, and source/identity groups spanning splits.

### Prediction — `contracts/schemas/prediction.schema.json`

One JSONL object per clip × configuration. Required fields: `run_id`, `clip_id`, `split`, `config`, `score_fake`, `checkpoint_sha256`. Supported configuration identifiers are `reference`, `low_precision`, `restore_value_output`, `restore_query`. Prediction records must not include ground-truth labels; the evaluator joins those from the manifest. The UI supports selecting/importing multiple prediction files together.

### Evaluation — `scripts/m2_evaluate.py`

Input: manifest JSONL, one or more prediction JSONL files, and (for evaluation) a validation-frozen protocol JSON. Output under the selected report directory: `metrics.json`, `summary.md`, `curves.png`, `recall_by_type.png`. The JSON contains overall `auroc`, `auprc`, `bce`, `recall`, `real_fpr`, per-type blocks and paired comparisons. The evaluator compares each fake type against all real clips in that split, uses source/identity cluster bootstrap intervals, and only opens test scoring through the explicit unseal/purpose path.

The UI visualizes supplied metrics; it does not calculate AUROC/AUPRC in the browser. For local `metrics.json`, it can also show the PNGs generated by the backend beside the JSON file.

### Benchmark — `contracts/schemas/benchmark.schema.json`

One JSONL record per configuration × device × backend × scope. Main scopes:

- `operator`: isolated `fusion_attention()` call on prebuilt Q/K/V tensors.
- `cached_feature_model`: cached-feature fusion + detection head; excludes raw media decode and encoder extraction.
- `preprocessing_once`: one-time raw-media preprocessing, separately recorded.

The record includes `p50_ms`, `p95_ms`, mean/median, timing samples or a reference, memory value and method, precision disclosure, workload, environment metadata and conversion-overhead fields. `peak_memory_bytes: null` means not measured, not zero. The backend only claims resettable peak allocator memory on CUDA; CPU/MPS peak memory remains unavailable.

`operator_benchmark.py` currently supports `sdpa` and `dense_oracle`; no `custom_tiled` backend is present. Dense oracle is for correctness, not a performance substitute. The dense score-matrix estimate is theoretical and is not the allocation of fused SDPA.

### Environment — `scripts/check_environment.py`

Produces `artifacts/runs/environment_report.json`. It records Python, OS, CPU/RAM, PyTorch, CUDA/MPS/device availability and tiny FP32/FP16/BF16/SDPA operation checks. It is a capability diagnostic, not a performance benchmark and not proof that the research model supports each dtype. INT8 hardware is not tested; the project uses floating-point fake quantization.

### Run provenance — `member3_runtime/artifacts.py`

A finalized run directory may contain `resolved_config.json`, `environment_report.json`, `provenance.json`, `benchmark_records.jsonl`, optional `stage_profile.json`, `run_manifest.json` and `integrity/artifact_hashes.json`. The UI exposes config/provenance, benchmark records, stage profiles and calls the backend's `verify_run_integrity()` for a selected run. Integrity hashes catch accidental changes but are not tamper-proof if all anchors are rewritten.

### Pipeline stage profile — `member3_runtime/stage_profiler.py`

Stage profiles distinguish one-time preprocessing from cached-feature fusion/head. Each stage explicitly declares whether it was measured; missing stages are `not_provided`, never zero. Combined stages stay combined. The profiler explicitly sets `end_to_end_measured: false`; independently measured stage timings must not be summed as end-to-end latency. The UI preserves those semantics.

### Member 1 diagnostic reports

- `scripts/day2_inference.py`: `artifacts/day2/ablation_report.json`, with checkpoint SHA, device, summary deltas and per-feature-file `reference`, `zero_audio`, `zero_video`, logit/output changes and valid length. Its `fake_score` keys are specific to the ablation report and are not the shared prediction JSONL fields.
- `scripts/day2_attention_audit.py`: `artifacts/day2/attention_audit.json`, with checkpoint SHA, feature path, valid token length, model config, mask semantics and per-layer Q/K/V shapes, `N_q`, `N_k`, head dimension, dtype and mask checks. The observed DiMoDif operation is joint-sequence self-attention, not proven separate-stream cross-attention.
- `scripts/dayA_memory_analysis.py`: `artifacts/dayA/attention_memory.json`, with per-layer theoretical dense score-matrix and QKV sizes. Its interpretation explicitly says this is not the measured SDPA allocation.
- `scripts/dayA_padding_audit.py`: `artifacts/dayA/padding_mask_audit.json`, with valid/max sequence lengths, pad counts, zero-padding checks, mask semantics and permitted attention-pair counts.

### Data quality / readiness reports

- `scripts/m2_audit.py` / whole-video counterpart: `shortcut_audit.json` plus Markdown summary. A shortcut feature is flagged at shortcut AUROC ≥ 0.65. A flag means the feature alone separates classes; it does not prove the detector uses it.
- `scripts/m2_train_overlap.py`: `train_overlap.json`, source overlap between evaluation videos and checkpoint training data.
- `scripts/m2_check_predictions.py`: caller-named `check_*.json`, contract, checkpoint hash, completeness and score-direction check; it is not an accuracy report.
- `scripts/m2_shortcut_control.py`: `shortcut_control.json` and Markdown summary comparing detector AUROC on all videos with a feature-matched subset; this is a follow-up control for a flagged nuisance feature.
- `scripts/m2_evaluate.py`: validation threshold and held-out test access protections.

## 4. Feature/media handling decision

The repository does not expose a raw-video/audio upload-to-prediction endpoint. Raw licensed clips belong to Member 2's offline processing and feature-cache workflow. Therefore the UI does not offer raw media upload or arbitrary model checkpoint upload.

The shared cache helper `member2_data/cache.py` expects a `.pt` tensor dictionary containing `audio_tokens` and `video_tokens`. The DiMoDif handoff notes describe `.npz` arrays named `audio_features` and `video_features`, while `DiMoDifAdapter.prepare_features()` expects a mapping with `audio_tokens` and `video_tokens`. Because these are not identical keys/formats, the UI only inspects `.pt`/`.npz` metadata and explicitly warns about the bridge; it does not rename or convert feature payloads invisibly.

JSON/JSONL reports can be imported into the current local Streamlit session for inspection. Those uploads are not copied into the repository by the app. Users may place canonical files into the documented local `data/` and `artifacts/` locations to enable automatic discovery on the next run.

| Benchmarks | benchmark schema v0.2 proposal, `benchmark_records.jsonl` / `benchmarks/*.jsonl` | import multiple records and filter by scope/config/device |
| Runs & system | environment report, `RunContext` layout, `verify_run_integrity`, `stage_profile.json` | run environment diagnostics, inspect hashes/config and verify integrity |
| Artifact import | repository artifact paths and input contracts | learn which files are safe/useful to import |

## 6. What the UI deliberately does not claim

- It is not a deepfake detector and does not create new scores.
- It does not claim live inference, four-mode inference or raw-media upload support.
- It does not treat simulated INT8 latency as hardware INT8 speedup.
- It does not invent CPU/MPS peak memory values.
- It does not sum independently timed stages into an end-to-end number.
- It does not tune from held-out test results.
- It does not present a documented Markdown validation table as a current structured test report.
